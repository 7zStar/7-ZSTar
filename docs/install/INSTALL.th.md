เอกสารนี้อธิบายรายละเอียดที่อยู่เบื้องหลังฉบับย่อใน [README](../readme/README.th.md) ได้แก่ ข้อกำหนดของระบบ คำเตือนของ SmartScreen การควบคุมแอปแบบอัจฉริยะ และวิธีตรวจสอบไฟล์ที่ดาวน์โหลด แพ็กเกจทั้งสามแบบ เมนูคลิกขวาของ Windows 11 การเชื่อมโยงไฟล์ และการถอนการติดตั้ง

## ข้อกำหนดของระบบ

**Windows 7 หรือ Windows Server 2008 R2, x64 หรือ x86 ส่วน arm64 ต้องใช้ Windows 10**
ไม่ต้องใช้อะไรเพิ่มเติม: ไลบรารีรันไทม์ C ถูกลิงก์แบบสแตติก (`-MT`) ไฟล์ปฏิบัติการจึงเรียกใช้เฉพาะ DLL ของ Windows เอง ไม่ต้องติดตั้ง redistributable และไม่ต้องใช้ .NET

ข้อกำหนดขั้นต่ำนี้ *คำนวณ* จากสิ่งที่แพ็กเกจต้องการ และได้ทดสอบบน Windows 7 SP1 ที่ติดตั้งการอัปเดตรุ่นหลังแล้ว (รวมถึง PowerShell 5.1), Windows 10 22H2 และ Windows 11 โดยทั้งหมดเป็น 64 บิต บน Windows 7 และ 10 การทดสอบครอบคลุมการติดตั้งและถอนการติดตั้ง `.msi` แบบ x64 ทั้งแบบทุกบัญชีและแบบเฉพาะผู้ใช้, วิซาร์ดติดตั้ง, `.zip` แบบ x64, โคเดกที่เพิ่มเข้ามาทุกตัวและรูปแบบ tar แบบขั้นตอนเดียวทุกรูปแบบ, เมนูคลิกขวา, การเชื่อมโยงไฟล์ และไฟล์วิธีใช้ รวมถึง `.msi` และ `.zip` แบบ x86 ที่ทำงานบน Windows 64 บิต นอกเหนือจากนี้ยังไม่ได้ทดสอบบน Windows เลย ไม่ว่าจะเป็น Windows 8 หรือ 8.1, Windows Server, Windows 32 บิต, ฮาร์ดแวร์ arm64 หรือ Windows 7 ที่ไม่มีการอัปเดตดังกล่าว ข้อกำหนดขั้นต่ำนี้ยังสูงกว่าของ 7-Zip ต้นทางด้วย ซึ่งไบนารีของต้นทางยังโหลดบน Windows XP ได้ มีสามสิ่งที่ทำให้เกณฑ์อยู่ที่ระดับนี้ และข้อที่สองคือข้อที่การตั้งค่าบิลด์ใดก็แก้ไม่ได้:

- `.msi` ประกาศ `InstallerVersion="500"` และ Windows Installer 5.0 ถูกจัดส่งมา "with Windows Server 2008 R2 and later and Windows 7 and later" (คือ Windows Server 2008 R2 ขึ้นไป และ Windows 7 ขึ้นไป) ([Microsoft][msi-versions]) `.zip` แบบพกพาไม่ผ่าน Windows Installer แต่ดูสองข้อถัดไป
- **zstd และ fast-lzma2 ใช้กลไกซิงโครไนซ์ที่มีเฉพาะ Vista ขึ้นไป** ทั้งสองกำหนด `_WIN32_WINNT 0x0600` ไว้ในเฮดเดอร์ของตัวเอง และเรียก `InitializeConditionVariable` / `SleepConditionVariableCS` โดยตรง ดังนั้น `7z.dll` และ `7za.exe` ซึ่งเป็นไบนารีสองตัวที่คอมไพล์โคเดกเหล่านี้รวมไว้ จึงนำเข้าฟังก์ชันสี่ฟังก์ชันที่ Windows XP และ Server 2003 ไม่มี ส่วน `7z.dll` ของต้นทางไม่นำเข้าฟังก์ชันเหล่านั้นเลย
- ชุดเครื่องมือบิลด์: ไบนารีเหล่านี้สร้างด้วย Visual Studio 2022 ซึ่งรายการเป้าหมายที่รองรับคือ Windows 7 ขึ้นไป ส่วน Vista และ Server 2008 เป็น "No" ([Microsoft][vs-targeting]) เวอร์ชันซับซิสเต็มที่ลิงก์คือ 6.0 บน x64 และ x86 และ 6.2 บน arm64 และ Windows บน arm64 เริ่มต้นที่ Windows 10 อยู่แล้วไม่ว่ากรณีใด

Windows Vista และ Server 2008 อยู่ในช่วงกลาง: ไบนารีน่าจะโหลดได้ แต่ชุดเครื่องมือบิลด์ไม่รองรับ ตัวติดตั้งจะไม่ทำงานที่นั่น และ 7-ZSTar ไม่ได้ทดสอบบนระบบเหล่านั้น

**Linux รองรับเฉพาะการบิลด์เป็นโปรแกรมบรรทัดคำสั่งเท่านั้น และไม่รองรับ macOS**
ฟอร์กนี้สร้าง `7zz` แบบเนทีฟ (โปรแกรมคอนโซล `Alone2`) ด้วย gcc ผ่าน makefile ของตัวเอง ซึ่งอินคลูด makefile ของต้นทางเข้ามาโดยไม่แก้ไขไฟล์ของต้นทางเลยสักไฟล์: `cd CPP/7zip/Bundles/Alone2 && make -j"$(nproc)" -f makefile.7zstar.gcc`
ได้บิลด์และทดสอบเฉพาะบน Ubuntu 24.04 กับ gcc 13.3 (x86-64): การบิลด์ด้วยแฟล็กของต้นทางไม่มีคำเตือนเลย การทดสอบเบื้องต้น 77 รายการผ่านทั้งหมด และเวกเตอร์ทดสอบการทำงานร่วมกัน 25 รายการที่สร้างบน Windows กับ 37 รายการที่สร้างบน Linux ให้ผลตัดสินเหมือนกับบน Windows ไฟล์สองไฟล์ที่เป็นของฟอร์กนี้ซึ่งการพอร์ตแตะต้อง ยังบิลด์บน Windows ได้โดยไม่ต้องแก้ไข (บิลด์ x64 ใหม่ทั้งหมด การทดสอบเบื้องต้น และการอ่านย้อนกลับเพื่อทดสอบการทำงานร่วมกันผ่านทั้งหมด) ไม่มี GUI เป้าหมาย Linux อื่นของต้นทาง (`7za`, `7zr`, `7z.so`) ไม่รองรับ: รายการออบเจ็กต์ gcc ของเป้าหมายเหล่านั้นไม่มีสิ่งที่การเปลี่ยนแปลงของฟอร์กต่อตัวจัดการของต้นทางต้องใช้ จึงคาดว่าจะลิงก์ไม่ผ่าน สถาปัตยกรรม ดิสทริบิวชัน และคอมไพเลอร์อื่นยังไม่ได้ตรวจสอบ และ macOS ไม่เคยถูกบิลด์เลย จึงไม่สามารถระบุ `MACOSX_DEPLOYMENT_TARGET` ได้ ขั้นตอนบิลด์ การทดสอบ และข้อจำกัดที่ทราบอยู่ใน `build/linux/README.md` ส่วนการทำงานร่วมกับเครื่องมือบน Linux อยู่ใน `test/interop/REPORT.md`

## แพ็กเกจที่ไม่มีลายเซ็น, SmartScreen และการควบคุมแอปแบบอัจฉริยะ

**ตัวติดตั้งและโปรแกรมในรีลีสของ 7-ZSTar ไม่ได้ลงนามโค้ดโดยผู้ออกใบรับรอง** และโปรเจกต์นี้ไม่มีใบรับรองสำหรับลงนามโค้ด Windows จึงไม่สามารถบอกได้ว่าใครเป็นผู้เผยแพร่ไฟล์ และเมื่อคุณเรียกใช้ `.msi` หรือโปรแกรมจาก `.zip` เป็นครั้งแรก Microsoft Defender SmartScreen อาจหยุดไว้พร้อมคำเตือน เอกสารสำหรับนักพัฒนาของ Microsoft ระบุ "No signature" เป็นหนึ่งในกรณีที่แสดงคำเตือนซึ่งมีชื่อว่า "Windows ให้การปกป้องพีซีของคุณแล้ว" โดยผู้ใช้ต้องเลือก "ยืนยันการเรียกใช้" ก่อน แอปจึงจะทำงาน ([Microsoft][smartscreen-rep]) นโยบายขององค์กรสามารถตัดตัวเลือกนั้นออกไปได้ทั้งหมด หากเป็นพีซีลักษณะนั้น ให้สอบถามผู้ที่ดูแลเครื่อง

สิ่งเดียวในรีลีสที่*มี*การลงนาม คือแพ็กเกจขนาดเล็กที่นำ 7-ZSTar ไปไว้ที่ระดับแรกของเมนูคลิกขวาของ Windows 11 ซึ่งอยู่ภายใน `.msi` แบบทุกบัญชี ใบรับรองของแพ็กเกจนี้ลงนามด้วยตัวเองและถูกสร้างขึ้นระหว่างการบิลด์แพ็กเกจเดียวนั้น จึงไม่ใช่ลายเซ็นของผู้ออกใบรับรอง และไม่ได้บอกอะไรเกี่ยวกับผู้ที่สร้างแพ็กเกจ ดู [เมนูคลิกขวาของ Windows 11](#เมนูคลิกขวาของ-windows-11) เพื่อดูว่ามันทำอะไรและจะปฏิเสธได้อย่างไร

คำเตือนไม่ใช่หลักฐานว่าไฟล์ไม่ดี และการไม่มีคำเตือนก็ไม่ใช่หลักฐานว่าไฟล์ดี สิ่งที่คุณตรวจสอบเองได้คือสำเนาของคุณตรงกับไฟล์ที่เผยแพร่บนหน้ารีลีสทุกประการหรือไม่ ทุกรีลีสมีไฟล์ชื่อ `SHA256SUMS` ซึ่งมีหนึ่งบรรทัดต่อหนึ่งแพ็กเกจ เป็นค่าแฮช SHA-256 ตามด้วยชื่อไฟล์

1. ดาวน์โหลดแพ็กเกจและ `SHA256SUMS` จากหน้ารีลีสเดียวกัน ลงในโฟลเดอร์เดียวกัน
2. เปิด PowerShell ในโฟลเดอร์นั้นแล้วเปรียบเทียบ โดยแทนที่ชื่อด้วยไฟล์ที่คุณดาวน์โหลด:

   ```powershell
   $name = '7-ZSTar-26.05.1-x64.msi'
   $expected = ((Get-Content .\SHA256SUMS | Where-Object { $_ -match ([regex]::Escape($name) + '$') }) -split '\s+')[0]
   $actual   = (Get-FileHash -Algorithm SHA256 -LiteralPath $name).Hash
   $actual -eq $expected
   ```

   `True` หมายความว่าค่าแฮชทั้งสองตรงกันทุกประการ หากต้องการดูค่าด้วยตัวเองแทน ให้รัน
   `Get-FileHash -Algorithm SHA256 .\7-ZSTar-26.05.1-x64.msi` แล้วหาชื่อไฟล์เดียวกันใน `SHA256SUMS` การเปรียบเทียบไม่สนใจตัวพิมพ์ใหญ่หรือเล็ก
3. หากได้ `False` หรือไม่มีชื่อไฟล์อยู่ใน `SHA256SUMS` อย่าเรียกใช้ไฟล์นั้น: ลบไฟล์แล้วดาวน์โหลดใหม่ หากยังไม่ตรงกัน โปรดแจ้งตามที่อธิบายไว้ใน [SECURITY.md](../../SECURITY.md)

`SHA256SUMS` ครอบคลุมเฉพาะไฟล์ที่อัปโหลดไปยังรีลีสนั้น การบิลด์แท็กเดียวกันด้วยตัวเองจะได้ค่าแฮชที่ต่างออกไป (แพ็กเกจเมนูคลิกขวาถูกลงนามด้วยใบรับรองใหม่ทุกครั้งที่บิลด์) และซอร์สโค้ดถูกเผยแพร่ไว้ในทุกรีลีสหากคุณต้องการบิลด์เอง: ดู [build/README.md](../../build/README.md)

เมื่อค่าแฮชตรงกันและคุณมั่นใจในแหล่งที่มาของไฟล์แล้ว:

- **`.msi`**: เริ่มต้นตามปกติ หาก SmartScreen หยุดไว้ ให้เลือกตัวเลือกที่ให้เรียกใช้ต่อ ("Run anyway" บน Windows ภาษาอังกฤษ) หน้าต่างคำเตือนอาจต้องขยายออกก่อน: บนเครื่อง Windows 10 ที่ทดสอบ มีเพียงปุ่มไม่ให้เรียกใช้ไฟล์ ("ไม่ต้องเรียกใช้") จนกว่าจะคลิกลิงก์ "ข้อมูลเพิ่มเติม" ใต้ข้อความ จากนั้น `.msi` แบบทุกบัญชีจะขอการอนุมัติจากผู้ดูแลเหมือนตัวติดตั้งทั่วไป
- **`.zip`**: แตกไฟล์แล้วเริ่ม `7zFM.exe` หรือ `7z.exe` จากโฟลเดอร์ โปรแกรมข้างในก็ไม่ได้ลงนามเช่นกัน Windows จึงอาจแสดงคำเตือนแบบเดียวกันเมื่อคุณเริ่มแต่ละโปรแกรมเป็นครั้งแรก

SmartScreen เตือนตามระดับความเป็นที่รู้จักของไฟล์ ไม่ใช่แค่ตามลายเซ็น ไฟล์ที่มีคนดาวน์โหลดน้อยอาจทำให้เกิดคำเตือนได้แม้จะลงนามแล้ว สิ่งที่อธิบายไว้ในที่นี้ไม่ได้เปลี่ยนเรื่องนั้น และไม่มีขั้นตอนใดข้างต้นที่ปิด SmartScreen

### การควบคุมแอปแบบอัจฉริยะบน Windows 11

พีซี Windows 11 บางเครื่องเปิดการป้องกันที่เข้มงวดกว่า เรียกว่า **การควบคุมแอปแบบอัจฉริยะ** ไว้ เมื่อเปิดอยู่ Windows จะบล็อกไฟล์ที่ไม่ได้ลงนาม เว้นแต่บริการคลาวด์ของ Microsoft จะรับรองไฟล์นั้นได้ และรีลีสใหม่มักยังไม่มีบันทึกดังกล่าว ([Microsoft][sac-faq], [Microsoft][smartscreen-rep]) ต่างจากคำเตือนของ SmartScreen การบล็อกนี้ไม่มีตัวเลือกให้เรียกใช้ไฟล์ต่อ และคำถามที่พบบ่อยของ Microsoft ระบุว่าไม่มีวิธีข้ามการควบคุมแอปแบบอัจฉริยะสำหรับแอปรายตัว

สิ่งที่เกิดขึ้นเมื่อลอง 7-ZSTar 26.05.1 บน Windows 11 Pro 25H2 (build 26200.8037) โดยเปิดการควบคุมแอปแบบอัจฉริยะไว้:

- **ตัวติดตั้ง `.msi` ถูกบล็อก** ทั้งแบบทุกบัญชีและแบบเฉพาะผู้ใช้ บน Windows ภาษาจีนตัวเต็ม Windows Installer แสดงข้อความ 「系統禁用此安裝。請連絡系統管理員。」 และการแจ้งเตือนของความปลอดภัยของ Windows ระบุว่าการควบคุมแอปแบบอัจฉริยะบล็อกไฟล์ เพราะ Windows ไม่สามารถบอกได้ว่าใครเป็นผู้เผยแพร่ และไม่ใช่แอปที่ Windows รู้จัก ไม่มีตัวเลือกให้ดำเนินการต่อ และ `msiexec /i ... /qn` คืนค่า error 1625 ข้อความนั้นคือ string 1625 ของ Windows Installer ส่วนบน Windows ภาษาอังกฤษ สตริงเดียวกันอ่านว่า "The system administrator has set policies to prevent this installation." (อ่านจากรีซอร์สภาษาอังกฤษของ Windows Installer ไม่ได้เห็นบนหน้าจอ)
- **โปรแกรมจาก `.zip` ทำงานได้** `7zFM.exe` ที่แตกออกมาจาก `.zip` แบบพกพาเริ่มทำงานตามปกติในการทดสอบเดียวกัน การที่ Windows ยอมให้โปรแกรมที่ไม่ได้ลงนามทำงานหรือไม่ เป็นการตัดสินไฟล์นั้นของ Windows เอง ดังนั้นบนพีซีของคุณอาจต่างออกไป
- หลังจากเปิดการควบคุมแอปแบบอัจฉริยะได้ไม่นาน `.msi` ติดตั้งได้อยู่สองสามนาทีก่อนที่จะเริ่มถูกบล็อก ยังไม่พบสาเหตุ ดังนั้นการติดตั้งสำเร็จทันทีหลังเปิดจึงไม่ได้หมายความว่าตัวติดตั้งได้รับอนุญาต

ดังนั้นบนพีซีที่เปิดการควบคุมแอปแบบอัจฉริยะอยู่ **จึงติดตั้งตัวติดตั้งไม่ได้** และการตรวจสอบ `SHA256SUMS` ก็ไม่ได้เปลี่ยนเรื่องนั้น สิ่งที่เปลี่ยนได้คือการปิดการควบคุมแอปแบบอัจฉริยะใน การตั้งค่าการควบคุมแอปแบบอัจฉริยะ ของแอปความปลอดภัยของ Windows (บน Windows ภาษาจีนตัวเต็มที่ทดสอบ: Windows 安全性, 應用程式與瀏覽器控制, 智慧型應用程式控制設定) ในการทดสอบ การเลือกตัวเลือกปิดมีผลทันทีโดยไม่ต้องรีสตาร์ท และตัวติดตั้งก็ติดตั้งได้ นี่เป็นการตั้งค่าของทั้งพีซี และไม่มีส่วนใดในที่นี้ขอให้คุณเปลี่ยน: เป็นเรื่องที่คุณตัดสินใจเอง หรือเป็นของผู้ดูแลหากเป็นพีซีที่มีผู้ดูแล

ควรทราบล่วงหน้าด้วยว่าจะเปิดกลับได้หรือไม่ คำถามที่พบบ่อยของ Microsoft ระบุว่าการอัปเดต Windows ล่าสุดทำให้เปิดการควบคุมแอปแบบอัจฉริยะอีกครั้งได้โดยไม่ต้องติดตั้ง Windows ใหม่ทั้งหมด ดังนั้นบนเวอร์ชันที่ไม่มีการอัปเดตเหล่านั้น การปิดอาจเป็นการปิดถาวร บนบิลด์ที่ทดสอบ ตัวเลือกสำหรับเปิดยังคงปรากฏอยู่หลังจากปิดแล้ว นั่นเป็นผลการทดสอบ ไม่ใช่คำรับรองสำหรับเวอร์ชันของคุณ

## การติดตั้ง

แพ็กเกจสามแบบ ทั้งหมดสร้างด้วย `installer\Build-Package.ps1` (แบบเฉพาะผู้ใช้ใช้ `-PerUser`):

| | `.msi` | `-user.msi` | `.zip` |
|---|---|---|---|
| ติดตั้งให้ | ทุกบัญชี | บัญชีที่ติดตั้ง | - |
| เมนูคลิกขวาของ File Explorer | มี | มี เฉพาะเมนูแบบคลาสสิก ([ด้านล่าง](#แพ็กเกจแบบเฉพาะผู้ใช้)) | ไม่มี |
| รายการในเมนูเริ่ม | มี | มี | ไม่มี |
| ต้องใช้ผู้ดูแล | ต้อง | ไม่ต้อง | ไม่ต้อง |
| การถอนการติดตั้ง | *แอปที่ติดตั้ง* ในการตั้งค่า | *แอปที่ติดตั้ง* ในการตั้งค่า | ลบโฟลเดอร์ |

*แอปที่ติดตั้ง* คือชื่อใน Windows 11 ส่วน Windows 10 เรียกหน้าเดียวกันว่า *แอปและคุณลักษณะ* และบน Windows 7 คือ *โปรแกรมและคุณลักษณะ* ใน แผงควบคุม

ให้ใช้แพ็กเกจที่ตรงกับตัว Windows: x86 บน Windows 32 บิต, x64 บน Windows 64 บิต, arm64 บน Windows on Arm (แพ็กเกจ arm64 ถูกบิลด์ไว้แล้วแต่ไม่เคยถูกรัน) ส่วนขยายเชลล์แบบ x86 เป็น 32 บิต และ File Explorer แบบ 64 บิตโหลดมันไม่ได้ ดังนั้นบน Windows 64 บิต `-user.msi` แบบ x86 จึงไม่มีเมนูคลิกขวาเลย และ `.msi` แบบ x86 มีเมนูนี้เฉพาะบน Windows 11 และเฉพาะบัญชีที่ลงทะเบียนแพ็กเกจ Windows 11 ของมัน (บัญชีที่ติดตั้ง หรือบัญชีที่รัน `-Register` ตามที่อธิบายด้านล่าง)

MSI ติดตั้งลงใน `Program Files\7-ZSTar` เสมอ: ต่างจากแพ็กเกจแบบเฉพาะผู้ใช้ ตรงที่ไม่ให้เลือกโฟลเดอร์ และไม่สนใจ `INSTALLFOLDER` ในบรรทัดคำสั่ง เพราะโฟลเดอร์นั้นเก็บสคริปต์ที่ตัวติดตั้งรันในฐานะ SYSTEM และ DLL ที่ File Explorer ของทุกผู้ใช้โหลด และโฟลเดอร์ที่สร้างไว้ที่อื่น (เช่นใต้ `C:\`) ทุกผู้ใช้เขียนได้ มันลงทะเบียน CLSID ของส่วนขยายเชลล์ของตัวเอง และรีจิสทรีฮีฟ `Software\7-ZSTar` ของตัวเอง และตั้งชื่อคีย์เมนูบริบททุกคีย์ว่า `7-ZSTar` จึงไม่ชนกับและไม่ลบของ 7-Zip ทางการ ดู [installer/GUIDS.md](../../installer/GUIDS.md)

มันแสดงวิซาร์ดติดตั้งตามปกติ - welcome, licence, setup type, optional feature tree, finish (หน้าต้อนรับ ข้อตกลงสัญญาอนุญาต ประเภทการติดตั้ง แผนผังคุณลักษณะที่เลือกได้ และหน้าสุดท้าย) - และการติดตั้งแบบเงียบก็ยังใช้ได้เหมือนเดิม (`msiexec /i 7-ZSTar-<version>-<arch>.msi /qn`) เพราะ msiexec ข้ามลำดับ UI ทั้งหมดในโหมดเงียบ วิซาร์ดเป็นภาษาอังกฤษเท่านั้น แม้บน Windows ที่ตั้งเป็นภาษาอื่น (พบบน Windows 10 ภาษาจีนตัวเต็ม; `.msi` ถูกบิลด์โดยไม่มีภาษาอื่น) และหน้าสุดท้ายมีช่อง *Launch 7-ZSTar File Manager* ที่ถูกเลือกไว้เป็นค่าเริ่มต้น

### เมนูคลิกขวาของ Windows 11

บน Windows 11 รายการนี้อยู่ในเมนูระดับแรก ไม่ได้ซ่อนอยู่ใต้ *แสดงตัวเลือกเพิ่มเติม* เหมือนที่ 7-Zip ทางการและ WinRAR ยังอยู่ Windows 11 จะแสดงส่วนขยายเชลล์ที่นั่นก็ต่อเมื่อมาพร้อมข้อมูลระบุตัวตนของแพ็กเกจ MSI จึงแถมแพ็กเกจ MSIX ขนาดเล็กที่มีแต่ข้อมูลระบุตัวตนไว้ข้างโปรแกรม และลงทะเบียนมันระหว่างการติดตั้ง การลงทะเบียนแบบคลาสสิกยังคงไว้ด้วย มันคือสิ่งที่ทำให้รายการปรากฏในเมนูคลิกขวาบน Windows 10 และ Windows 7 ซึ่งเมนูมีระดับเดียวและไม่มี *แสดงตัวเลือกเพิ่มเติม* และเป็นสิ่งที่ทำให้เมนูยังใช้งานได้สำหรับผู้ที่เรียกคืนเมนูบริบทแบบเก่า

แพ็กเกจนั้นลงนามด้วย **ใบรับรองที่ลงนามด้วยตัวเอง** และตัวติดตั้งนำมันไปไว้ใน `LocalMachine\TrustedPeople` - Windows จะไม่ปรับใช้แพ็กเกจที่ลายเซ็นไม่สามารถโยงไปยังสิ่งที่เชื่อถือได้ การถอนการติดตั้งจะนำใบรับรองออกพร้อมกับแพ็กเกจ บน Windows 10 และ Windows 7 ตัวติดตั้งไม่ทำทั้งสองอย่าง: ไม่เพิ่มใบรับรองและไม่ลงทะเบียนแพ็กเกจ และการลงทะเบียนแบบคลาสสิกอย่างเดียวก็ให้เมนูนั้นได้

หากคุณไม่ต้องการเชื่อถือใบรับรองที่ลงนามด้วยตัวเอง ให้ปฏิเสธเฉพาะส่วนนั้นและคงส่วนอื่นไว้ทั้งหมด:

```
msiexec /i 7-ZSTar-<version>-<arch>.msi SPARSE=0
```

คุณจะได้เฉพาะเมนูแบบคลาสสิก ดังนั้นบน Windows 11 รายการ 7-ZSTar จะอยู่ในเมนูคลิกขวาภายใต้ *แสดงตัวเลือกเพิ่มเติม* หากต้องการเปิดรายการระดับแรกภายหลัง หรือยกเลิกหลังการติดตั้งตามปกติ:

```
powershell -ExecutionPolicy Bypass -File "C:\Program Files\7-ZSTar\Setup-ShellIntegration.ps1" -TrustCert -Register
powershell -ExecutionPolicy Bypass -File "C:\Program Files\7-ZSTar\Setup-ShellIntegration.ps1" -Unregister -UntrustCert
```

การเชื่อถือใบรับรองนั้นหมายความว่า Windows จะยอมรับแพ็กเกจ**อื่นใด**ที่ลงนามด้วยกุญแจเดียวกันโดยไม่เตือนด้วย ใบรับรองนี้ใช้กับแพ็กเกจนี้แพ็กเกจเดียวเท่านั้น และการถอนการติดตั้งจะนำมันออก แต่นั่นคือสิ่งที่คุณตกลงยอมรับ - `SPARSE=0` ข้างต้นคือวิธีปฏิเสธ

การลงทะเบียนแพ็กเกจเป็นแบบต่อผู้ใช้ และตัวติดตั้งรันให้เฉพาะผู้ที่ติดตั้ง ซึ่งมีผลสองข้อ:

- บัญชีที่สองบนเครื่องเดียวกันจะได้เมนูแบบคลาสสิกอย่างเดียว จนกว่าจะรันสคริปต์เดียวกันนั้นด้วย `-Register`
- การถอนการติดตั้งจะยกเลิกการลงทะเบียนให้เฉพาะผู้ที่ถอนเท่านั้น หากมีคนอื่นลงทะเบียนไว้ การลงทะเบียนของเขาจะยังอยู่หลังการถอนการติดตั้ง และชี้ไปยังโฟลเดอร์ที่ไม่มีอยู่แล้ว บัญชีนั้นล้างได้ด้วย `Get-AppxPackage 7-ZSTar | Remove-AppxPackage`

**ข้อจำกัดที่ทราบ: เมนูระดับแรกจะถูกลงทะเบียนก็ต่อเมื่อการติดตั้งรันในเซสชันแบบโต้ตอบที่ลงชื่อเข้าใช้อยู่เท่านั้น** การติดตั้ง `.msi` แบบทุกบัญชีจากเซสชันระยะไกลหรือเซสชันที่ไม่โต้ตอบ - ผ่าน SSH หรือการติดตั้งแบบเงียบจากเครื่องมือจัดการ - ยังคงรายงานว่าสำเร็จ แต่แพ็กเกจ Windows 11 ไม่ถูกลงทะเบียน จึงปรากฏเฉพาะเมนูแบบคลาสสิกใต้ *แสดงตัวเลือกเพิ่มเติม* ในการทดสอบ `msiexec /i ... /qn` จากเซสชัน SSH (เซสชัน 0) จบด้วยรหัส 0 ขณะที่ `Setup-ShellIntegration.ps1` รายงาน `registration failed: 0x80070005` (Access is denied.) ส่วน `.msi` ตัวเดียวกันที่ติดตั้งจากเซสชันคอนโซลของผู้ดูแลลงทะเบียนได้ตามปกติ

`-Status` จะพิมพ์สิ่งที่มีอยู่และสิ่งที่ยังไม่มี

### แพ็กเกจแบบเฉพาะผู้ใช้

`7-ZSTar-<version>-<arch>-user.msi` ติดตั้งให้เฉพาะบัญชีปัจจุบัน ลงใน `%LOCALAPPDATA%\Programs\7-ZSTar` โดยไม่มีข้อความแจ้งของการควบคุมบัญชีผู้ใช้ (UAC) ทุกอย่างที่มันลงทะเบียนอยู่ใต้ `HKCU` แพ็กเกจไม่เขียนอะไรลง `HKLM` (นอกจากบันทึกภายในของ Windows Installer เอง) สิ่งที่มันไม่ทำแบบเดียวกับแพ็กเกจระดับเครื่อง:

- **ไม่มีเมนูระดับแรกของ Windows 11** บน Windows 11 7-ZSTar อยู่ในเมนูคลิกขวาภายใต้ *แสดงตัวเลือกเพิ่มเติม* รายการระดับแรกต้องให้ใบรับรองที่ลงนามด้วยตัวเองได้รับความเชื่อถือทั้งเครื่อง ซึ่งต้องใช้ผู้ดูแล: จากการวัดผลบน Windows 11 ใบรับรองใน `CurrentUser\TrustedPeople` ไม่เพียงพอให้ Windows ปรับใช้แพ็กเกจ แพ็กเกจแบบเฉพาะผู้ใช้จึงตัดส่วนนี้ออก
- **ติดตั้งได้อย่างใดอย่างหนึ่งต่อเครื่อง** แต่ละแพ็กเกจจะไม่ยอมติดตั้งขณะที่อีกแพ็กเกจติดตั้งอยู่ ให้ถอนการติดตั้งแบบหนึ่งก่อนติดตั้งอีกแบบ แพ็กเกจระดับเครื่องมองเห็นได้เฉพาะสำเนาแบบเฉพาะผู้ใช้ของบัญชีที่รันมันอยู่ จึงตรวจไม่พบการติดตั้งแบบเฉพาะผู้ใช้ของบัญชีอื่น
- **นโยบายกลุ่มอาจซ่อนเมนูของมัน** ในที่ที่ตั้งค่า `EnforceShellExtensionSecurity` ไว้ File Explorer จะโหลดเฉพาะส่วนขยายเชลล์ที่อยู่ใต้คีย์ *Approved* ระดับเครื่อง ซึ่งการติดตั้งแบบเฉพาะผู้ใช้เขียนไม่ได้ เมนูคลิกขวาจึงไม่ปรากฏ ให้ใช้แพ็กเกจระดับเครื่องในกรณีนี้
- **การล้างรูปแบบไฟล์ใน เครื่องมือ > ตัวเลือก > ระบบ จะลบสิ่งที่ 7-ZSTar เสนอสำหรับรูปแบบนั้นไปด้วย** เมื่อคุณล้างรูปแบบไฟล์ที่นั่น (คลิกเซลล์ของรูปแบบนั้นจนว่าง แล้วกด ตกลง) ตัวจัดการไฟล์จะลบคีย์ `HKCU\Software\Classes\.<ext>` และ `7-ZSTar.<ext>` ทั้งคีย์ - และสำหรับการติดตั้งแบบเฉพาะผู้ใช้ คีย์เหล่านั้นยังเก็บสิ่งที่แพ็กเกจลงทะเบียนไว้สำหรับ การตั้งค่า > แอป > แอปเริ่มต้น และรายการ *เปิดด้วย* ด้วย 7-ZSTar จึงหลุดจาก *เปิดด้วย* สำหรับรูปแบบนั้น และแอปเริ่มต้นจะแสดงรายการว่างสำหรับรูปแบบนั้น การซ่อมแซมการติดตั้งจะนำมันกลับมา (รัน `.msi` อีกครั้งแล้วเลือก *Repair*) ที่ดีกว่าคือกำหนดชนิดไฟล์ในแอปเริ่มต้น แทนการกำหนดในตัวจัดการไฟล์ แพ็กเกจระดับเครื่องมีจุดอ่อนแบบเดียวกันอยู่หนึ่งจุด ซึ่งอธิบายไว้ใต้หัวข้อการเชื่อมโยงไฟล์ด้านล่าง

### การเชื่อมโยงไฟล์ และสิ่งที่การถอนการติดตั้งทำกับมัน

**ให้ตั้งค่าที่ การตั้งค่า > แอป > แอปเริ่มต้น** บน Windows 11 พิมพ์ 7-ZSTar ที่นั่น แล้วทุกรูปแบบที่มันเปิดได้จะแสดงเป็นรายการให้กำหนด บน Windows 10 7-ZSTar อยู่ภายใต้ *Set defaults by app* (ตั้งค่าค่าเริ่มต้นตามแอป) ในหน้านั้น ซึ่ง *Manage* (จัดการ) จะแสดงรูปแบบของมัน Windows 7 ไม่มีแอปการตั้งค่า: 7-ZSTar อยู่ภายใต้ แผงควบคุม > โปรแกรมเริ่มต้น > *ตั้งค่าโปรแกรมเริ่มต้นของคุณ* ซึ่งเป็นสิ่งที่ *แอปเริ่มต้น* ในคู่มือนี้หมายถึงบน Windows 7 การกำหนดรูปแบบจากสองหน้านั้นยังไม่ได้ทดสอบ ตัวติดตั้งลงทะเบียน 7-ZSTar เป็นแอปพลิเคชันของโปรแกรมเริ่มต้น - มี ProgID ต่อหนึ่งรูปแบบพร้อมไอคอนและคำสั่งเปิด, รายการในรายการ *เปิดด้วย* ของแต่ละนามสกุล และบล็อก Capabilities ที่ Windows อ่าน - แต่จงใจไม่ยึดครองชนิดไฟล์ใด ๆ: โปรแกรมใดที่เปิดไฟล์เก็บถาวรของคุณเป็นการตัดสินใจของคุณ และนั่นคือสิ่งที่ทำให้ 7-ZSTar กับ 7-Zip ทางการไม่ขวางทางกัน Windows ยังคงส่งรูปแบบหนึ่งมาให้ 7-ZSTar เองได้เมื่อไม่มีโปรแกรมอื่นเสนอตัวเปิด: บนเครื่อง Windows 10 และ Windows 7 ที่ทดสอบ ซึ่งไม่มีโปรแกรมอื่นลงทะเบียน `.7z` ไว้ ไฟล์ `.7z` แสดงไอคอนของ 7-ZSTar และเปิดด้วย 7-ZSTar เมื่อดับเบิลคลิก โดย Windows ไม่ได้ถามว่าจะใช้โปรแกรมใด

**เครื่องมือ > ตัวเลือก > ระบบ ในตัวจัดการไฟล์ส่วนใหญ่ใช้ไม่ได้ผลบน Windows 11** และนั่นเป็นกฎของ Windows ไม่ใช่บั๊กที่นี่ มันเขียน ProgID ชื่อ `7-ZSTar.<ext>` ลงใน `HKCU\Software\Classes` และสำหรับนามสกุลใดก็ตามที่เครื่องรู้จักอยู่แล้ว - ทุกรูปแบบไฟล์เก็บถาวรเป็นเช่นนั้น - Windows 11 จะเพิกเฉย: `AssocQueryString` ตอบว่า `Unknown` และ File Explorer วาดไอคอนทั่วไปที่ว่างเปล่า สิ่งที่ Windows ยอมรับแทนคือคีย์ `UserChoice` ที่ประทับด้วยแฮชซึ่งมีเพียง Windows เท่านั้นที่คำนวณได้ จึงเป็นเหตุผลที่หน้าจอการตั้งค่าเป็นเส้นทางเดียวที่นั่น ไม่มีแอปพลิเคชันใดเขียนคีย์นี้ได้: ทั้ง 7-ZSTar, 7-Zip และตัวติดตั้งใดก็ตาม บน Windows 10 และ Windows 7 พฤติกรรมต่างออกไปในการทดสอบ: เมื่อตั้ง `.7z` และ `.zst` ในตัวจัดการไฟล์ โดยไม่ได้เลือกโปรแกรมอื่นสำหรับสองรูปแบบนั้น `AssocQueryString` คืนค่า `7zFM.exe` ทั้งสองรูปแบบ

**การล้างรูปแบบในคอลัมน์ *All Users* (ผู้ใช้ทั้งหมด) ของมัน จะลบการลงทะเบียนของแพ็กเกจระดับเครื่องสำหรับรูปแบบนั้น** คอลัมน์นั้นเขียนลง `HKLM\Software\Classes` ซึ่งแพ็กเกจระดับเครื่องเก็บ ProgID และรายการ *เปิดด้วย* ที่มันเสนอไว้ และการล้างรูปแบบที่นั่น (ซึ่งต้องรันตัวจัดการไฟล์ด้วย “ใช้งานในฐานะผู้ดูแล”) จะลบคีย์เหล่านั้นทั้งคีย์ - สำหรับทุกบัญชี การซ่อมแซมคืนคีย์ชุดเดียวกันสำหรับแพ็กเกจแบบเฉพาะผู้ใช้ ส่วนของแพ็กเกจระดับเครื่องนี้ยังไม่ได้วัดผล

**ไอคอนที่ยังว่างอยู่หลังจากเปลี่ยนแปลงอะไรก็ตาม** อาจเป็นแคชไอคอนของ File Explorer ด้วย ซึ่งไม่รู้ว่า DLL ที่แคชไว้แล้วถูกแทนที่ `ie4uinit.exe -show` ล้างแคชได้ไม่แน่นอน ให้ปิด File Explorer ลบ `%LOCALAPPDATA%\Microsoft\Windows\Explorer\iconcache_*.db` แล้วเริ่มใหม่

**การถอนการติดตั้งจะลบการเชื่อมโยงเท่าที่เข้าถึงได้** - ProgID `7-ZSTar.*` ของผู้ที่กำลังถอนการติดตั้ง และเฉพาะชนิดไฟล์ที่ยังชี้ไปที่ ProgID เหล่านั้น ดังนั้นรูปแบบที่ถูกมอบให้โปรแกรมอื่นในระหว่างนั้นจะไม่ถูกแตะต้อง การถอนการติดตั้งแพ็กเกจระดับเครื่องยังปล่อย ProgID ที่เปิดสำเนา 7-ZSTar ที่อื่นซึ่งยังมีอยู่ไว้เฉย ๆ ด้วย - เช่นสำเนาพกพาจาก `.zip` ที่ตั้งด้วย **เครื่องมือ > ตัวเลือก > ระบบ** ของสำเนานั้นเอง แพ็กเกจแบบเฉพาะผู้ใช้ทำเช่นนั้นไม่ได้: ProgID ของมันคือคีย์ `HKCU` ชุดเดียวกัน (ดู *แพ็กเกจแบบเฉพาะผู้ใช้* ข้างต้น) และการถอนการติดตั้งจะลบมัน ไม่ว่าใครเขียนไว้ทีหลังสุด การปล่อยไว้จะทำให้ชนิดไฟล์เหล่านั้นชี้ไปที่ ProgID ซึ่งไอคอนและคำสั่งเป็นไฟล์ปฏิบัติการที่ถูกลบไปแล้ว ซึ่งหมายถึงไอคอนว่างและข้อผิดพลาดเมื่อดับเบิลคลิก การเชื่อมโยงของบัญชีอื่นอยู่นอกการเข้าถึง: บัญชีเหล่านั้นล้างของตัวเองได้ด้วย `Setup-ShellIntegration.ps1 -RemoveAssociations` ก่อนที่โปรแกรมจะหายไป `msiexec /x ... KEEPASSOC=1` ข้ามขั้นตอนนี้ และการอัปเกรดไม่เคยทำขั้นตอนนี้

**ข้อจำกัดที่ทราบ: บัญชีอื่นยังคงการเชื่อมโยงที่ตั้งไว้เอง** การถอนการติดตั้งแพ็กเกจระดับเครื่องล้างเฉพาะสิ่งที่บัญชีที่รันการถอนการติดตั้งตั้งไว้ในคอลัมน์ของตัวเอง (คอลัมน์ที่มีชื่อบัญชีเป็นหัวคอลัมน์) ภายใต้ **เครื่องมือ > ตัวเลือก > ระบบ** ในตัวจัดการไฟล์ บัญชีอื่นที่ตั้งการเชื่อมโยงไว้ที่นั่นจะยังคงมันไว้ โดยชี้ไปยังโปรแกรมที่ถูกลบไปแล้ว ดังนั้นการดับเบิลคลิกไฟล์ `.7z` จะถามว่าจะใช้โปรแกรมใดใน Windows แต่ละบัญชีควรล้างของตัวเอง**ก่อน**การถอนการติดตั้งด้วย

```
powershell -ExecutionPolicy Bypass -File "C:\Program Files\7-ZSTar\Setup-ShellIntegration.ps1" -RemoveAssociations
```

ซึ่งลบเฉพาะรายการของ 7-ZSTar หรือหลังจากนั้นกำหนดชนิดไฟล์ใหม่ภายใต้ การตั้งค่า > แอป > แอปเริ่มต้น การทำในตัวจัดการไฟล์แทนหมายถึงการคลิกแต่ละเซลล์ในคอลัมน์ของตัวเองที่แสดง 7-ZSTar จนว่าง แล้วกด ตกลง อย่าเลือกทุกแถวแล้วกด "+" ซึ่งใช้สถานะเดียวกันกับทุกแถวที่เลือก จึงล้างรูปแบบที่เป็นของโปรแกรมอื่นไปด้วย เช่น 7-Zip ทางการ

การเชื่อมโยงที่ตั้งไว้ในคอลัมน์ **All Users** ไม่ถูกแตะต้องโดยการล้างตอนถอนการติดตั้งเลย และจะถูกปล่อยให้ทุกบัญชีชี้ไปยังโปรแกรมที่ถูกลบไปแล้ว ผู้ดูแลที่ตั้งไว้ควรล้างเซลล์เหล่านั้น จากตัวจัดการไฟล์ที่เรียกใช้ด้วย “ใช้งานในฐานะผู้ดูแล” แล้วกด ตกลง ก่อนถอนการติดตั้ง `-RemoveAssociations` เข้าไม่ถึงคอลัมน์นี้ การล้างทันทีก่อนถอนการติดตั้งไม่เป็นอันตราย แม้จะลบการลงทะเบียนของแพ็กเกจเองที่นั่นด้วย (ดังข้างต้น) เพราะการถอนการติดตั้งก็ลบมันอยู่แล้ว แพ็กเกจแบบเฉพาะผู้ใช้ไม่มีปัญหาเรื่องบัญชีอื่น และ 7-Zip ทางการก็ทำงานแบบเดียวกัน

## ภาษา

ทุกแพ็กเกจมีคำแปลของต้นทางมาด้วย กว่า 90 ภาษา เลือกได้ที่ **เครื่องมือ > ตัวเลือก > ภาษา** และ MSI ยังให้ตัดออกได้ภายใต้การติดตั้งแบบ *Custom* (กำหนดเอง) 7-ZSTar พยายามตามภาษาของระบบเมื่อเปิดครั้งแรก แต่การตรวจจับนั้นจะยอมแพ้และคงเป็นภาษาอังกฤษเมื่อ "ภาษาสำหรับโปรแกรมที่ไม่ใช่ Unicode" ของ Windows กับการตั้งค่ารูปแบบภูมิภาคไม่ตรงกัน - การเลือกภาษาด้วยตนเองใช้ได้เสมอ

สตริงที่ 7-ZSTar เพิ่มขึ้นเอง - ช่องระดับ zstd และพจนานุกรม ชื่อรูปแบบไฟล์เก็บถาวรใหม่ - ไม่มีคำแปลจากต้นทางและคงเป็นภาษาอังกฤษ ข้อยกเว้นคือปุ่ม **บริจาค** และ **เว็บไซต์** ในกล่องโต้ตอบเกี่ยวกับ 7-ZSTar: 67 จาก 92 ภาษามีคำแปลสำหรับแต่ละปุ่ม ส่วนอีก 25 ภาษาแสดงเป็นภาษาอังกฤษ (`Lang/UPSTREAM.md` ระบุรายการไว้)
คำแปลถูกนำเข้ามาทั้งชุดจากต้นทาง ไม่ได้เขียนขึ้นที่นี่: ดู [Lang/UPSTREAM.md](../../Lang/UPSTREAM.md)

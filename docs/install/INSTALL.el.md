## Απαιτήσεις συστήματος

**Windows 7 ή Windows Server 2008 R2, x64 ή x86. Σε arm64, Windows 10.**
Δεν χρειάζεται τίποτε άλλο: το C runtime είναι συνδεδεμένο στατικά (`-MT`), οπότε τα εκτελέσιμα δεν εισάγουν τίποτα εκτός από τα δικά τους DLL των Windows - χωρίς redistributable, χωρίς .NET.

Αυτό το κατώτατο όριο *προκύπτει* από όσα απαιτούν τα πακέτα και έχει δοκιμαστεί σε Windows 7 SP1 με εγκατεστημένες μεταγενέστερες ενημερώσεις (μεταξύ τους το PowerShell 5.1), σε Windows 10 22H2 και σε Windows 11, όλα 64-bit. Σε Windows 7 και 10 η δοκιμή κάλυψε την εγκατάσταση και την απεγκατάσταση του x64 `.msi` για όλους τους χρήστες και ανά χρήστη, τον οδηγό εγκατάστασης, το x64 `.zip`, κάθε πρόσθετο codec και κάθε μορφή tar ενός βήματος, το μενού δεξιού κλικ, τις συσχετίσεις αρχείων και το αρχείο βοήθειας, καθώς και το x86 `.msi` και `.zip` που εκτελούνται σε 64-bit Windows. Τίποτε άλλο δεν έχει δοκιμαστεί σε Windows: ούτε Windows 8 ή 8.1, ούτε Windows Server, ούτε 32-bit Windows, ούτε υλικό arm64, ούτε Windows 7 χωρίς αυτές τις ενημερώσεις. Το όριο είναι επίσης υψηλότερο από εκείνο του upstream 7-Zip, τα εκτελέσιμα του οποίου φορτώνονται ακόμη και σε Windows XP. Τρία πράγματα το ορίζουν εκεί, και το δεύτερο είναι αυτό που καμία ρύθμιση μεταγλώττισης δεν μπορεί να αναιρέσει:

- Το `.msi` δηλώνει `InstallerVersion="500"`, και το Windows Installer 5.0 διανεμήθηκε "with Windows Server 2008 R2 and later and Windows 7 and later"
  ([Microsoft][msi-versions]). Το φορητό `.zip` δεν περνά από το Windows Installer, αλλά δείτε τα επόμενα δύο σημεία.
- **Το zstd και το fast-lzma2 χρησιμοποιούν συγχρονισμό που υπάρχει μόνο από το Vista και μετά.** Και τα δύο επιβάλλουν `_WIN32_WINNT 0x0600` στις δικές τους κεφαλίδες και καλούν απευθείας τις `InitializeConditionVariable` / `SleepConditionVariableCS`, οπότε το `7z.dll` και το `7za.exe` - τα δύο εκτελέσιμα στα οποία είναι μεταγλωττισμένα τα codec - εισάγουν τέσσερις συναρτήσεις που τα Windows XP και Server 2003 δεν διαθέτουν. Το `7z.dll` του upstream δεν εισάγει καμία από αυτές.
- Η αλυσίδα εργαλείων: αυτά μεταγλωττίζονται με το Visual Studio 2022, του οποίου η λίστα υποστηριζόμενων στόχων είναι τα Windows 7 και μεταγενέστερα - τα Vista και Server 2008 είναι "No"
  ([Microsoft][vs-targeting]). Η έκδοση του συνδεδεμένου υποσυστήματος είναι 6.0 σε x64 και x86 και 6.2 σε arm64, και τα Windows σε arm64 ξεκινούν σε κάθε περίπτωση από τα Windows 10.

Τα Windows Vista και Server 2008 βρίσκονται ανάμεσα: τα εκτελέσιμα θα φορτώνονταν, αλλά η αλυσίδα εργαλείων δεν τα υποστηρίζει, το πρόγραμμα εγκατάστασης δεν θα εκτελεστεί εκεί, και το 7-ZSTar δεν έχει δοκιμαστεί σε αυτά.

**Το Linux υποστηρίζεται μόνο ως build γραμμής εντολών· το macOS δεν υποστηρίζεται.**
Το fork μεταγλωττίζει ένα εγγενές `7zz` (το πρόγραμμα κονσόλας `Alone2`) με gcc μέσω του δικού του makefile, το οποίο περιλαμβάνει εκείνα του upstream και δεν τροποποιεί κανένα από αυτά:
`cd CPP/7zip/Bundles/Alone2 && make -j"$(nproc)" -f makefile.7zstar.gcc`.
Έχει μεταγλωττιστεί και δοκιμαστεί μόνο σε Ubuntu 24.04 με gcc 13.3 (x86-64): το build δεν δίνει καμία προειδοποίηση με τις σημαίες του upstream, το smoke test των 77 ελέγχων περνά, και τα 25 διανύσματα διαλειτουργικότητας που φτιάχτηκαν σε Windows και τα 37 που φτιάχτηκαν σε Linux δίνουν τα ίδια αποτελέσματα όπως στα Windows. Τα δύο αρχεία του fork που άγγιξε η πόρτα εξακολουθούν να μεταγλωττίζονται αμετάβλητα στα Windows (καθαρό x64 build, smoke tests και ανάγνωση διαλειτουργικότητας περνούν όλα). Δεν υπάρχει γραφική διεπαφή. Οι άλλοι στόχοι Linux του upstream (`7za`, `7zr`, `7z.so`) δεν υποστηρίζονται: οι λίστες αντικειμένων gcc τους δεν περιέχουν όσα χρειάζονται οι αλλαγές του fork στους χειριστές του upstream, οπότε αναμένεται να αποτύχουν στη σύνδεση. Άλλες αρχιτεκτονικές, διανομές και μεταγλωττιστές δεν έχουν επαληθευτεί, και το macOS δεν έχει μεταγλωττιστεί ποτέ, οπότε δεν μπορεί να δηλωθεί κανένα `MACOSX_DEPLOYMENT_TARGET`. Τα βήματα μεταγλώττισης, οι δοκιμές και τα γνωστά όρια βρίσκονται στο `build/linux/README.md`· η διαλειτουργικότητα με εργαλεία Linux βρίσκεται στο `test/interop/REPORT.md`.

## Μη υπογεγραμμένα πακέτα, SmartScreen και Smart App Control

**Τα προγράμματα εγκατάστασης και τα προγράμματα μιας έκδοσης του 7-ZSTar δεν φέρουν ψηφιακή υπογραφή από αρχή πιστοποίησης**, και το έργο αυτό δεν διαθέτει πιστοποιητικό υπογραφής κώδικα.
Τα Windows επομένως δεν μπορούν να καταλάβουν ποιος δημοσίευσε το αρχείο, και όταν εκτελείτε για πρώτη φορά το `.msi`, ή ένα πρόγραμμα από το `.zip`, το *Microsoft Defender SmartScreen* μπορεί να το σταματήσει με μια προειδοποίηση. Η τεκμηρίωση προγραμματιστών της Microsoft αναφέρει το "No signature" ως μία από τις περιπτώσεις που εμφανίζουν προειδοποίηση με τίτλο "Windows protected your PC" (Τα Windows προστάτευσαν τον υπολογιστή σας), όπου ο χρήστης πρέπει να επιλέξει "Run anyway" (Εκτέλεση ούτως ή άλλως) για να εκτελεστεί η εφαρμογή ([Microsoft][smartscreen-rep]). Η πολιτική μιας επιχείρησης μπορεί να αφαιρέσει εντελώς αυτή την επιλογή· σε έναν τέτοιο υπολογιστή, ρωτήστε όποιον τον διαχειρίζεται.

Το μόνο πράγμα σε μια έκδοση που *είναι* υπογεγραμμένο είναι το μικρό πακέτο που βάζει το 7-ZSTar στο πρώτο επίπεδο του μενού δεξιού κλικ των Windows 11, μέσα στο `.msi` για όλους τους χρήστες. Το πιστοποιητικό του είναι αυτο-υπογεγραμμένο και δημιουργείται κατά την κατασκευή αυτού του ενός πακέτου, επομένως δεν είναι υπογραφή αρχής πιστοποίησης και δεν λέει τίποτα για το ποιος έφτιαξε το πακέτο· δείτε το [μενού δεξιού κλικ των Windows 11](#μενού-δεξιού-κλικ-των-windows-11) για το τι κάνει και πώς να το αρνηθείτε.

Η προειδοποίηση δεν αποτελεί απόδειξη ότι ένα αρχείο είναι κακό, και η απουσία της δεν θα ήταν απόδειξη ότι ένα αρχείο είναι καλό. Αυτό που μπορείτε να ελέγξετε μόνοι σας είναι ότι το αντίγραφό σας είναι ακριβώς αυτό που δημοσιεύτηκε στη σελίδα της έκδοσης. Κάθε έκδοση περιλαμβάνει ένα αρχείο με όνομα `SHA256SUMS`: μία γραμμή ανά πακέτο, ένα hash SHA-256 ακολουθούμενο από το όνομα του αρχείου.

1. Κάντε λήψη του πακέτου και του `SHA256SUMS` από την ίδια σελίδα έκδοσης, στον ίδιο φάκελο.
2. Ανοίξτε το PowerShell σε αυτόν τον φάκελο και συγκρίνετε. Αντικαταστήστε το όνομα με το αρχείο που κατεβάσατε:

   ```powershell
   $name = '7-ZSTar-26.05.1-x64.msi'
   $expected = ((Get-Content .\SHA256SUMS | Where-Object { $_ -match ([regex]::Escape($name) + '$') }) -split '\s+')[0]
   $actual   = (Get-FileHash -Algorithm SHA256 -LiteralPath $name).Hash
   $actual -eq $expected
   ```

   Το `True` σημαίνει ότι τα hash είναι ίδια. Για να τα δείτε μόνοι σας, εκτελέστε
   `Get-FileHash -Algorithm SHA256 .\7-ZSTar-26.05.1-x64.msi` και βρείτε το ίδιο
   όνομα αρχείου στο `SHA256SUMS`· η σύγκριση αγνοεί τα κεφαλαία και τα πεζά.
3. Αν πάρετε `False`, ή το όνομα του αρχείου δεν υπάρχει στο `SHA256SUMS`, μην το εκτελέσετε: διαγράψτε το αρχείο και κατεβάστε το ξανά. Αν και πάλι δεν ταιριάζει, αναφέρετέ το όπως περιγράφεται στο [SECURITY.md](../../SECURITY.md).

Το `SHA256SUMS` καλύπτει μόνο τα αρχεία που ανέβηκαν σε εκείνη την έκδοση. Αν μεταγλωττίσετε μόνοι σας το ίδιο tag, θα πάρετε διαφορετικά hash (το πακέτο του μενού δεξιού κλικ υπογράφεται με νέο πιστοποιητικό σε κάθε build), και ο πηγαίος κώδικας δημοσιεύεται με κάθε έκδοση, αν προτιμάτε να τον μεταγλωττίσετε: δείτε το [build/README.md](../../build/README.md).

Όταν τα hash ταιριάζουν και είστε ικανοποιημένοι με την προέλευση του αρχείου:

- **`.msi`** - ξεκινήστε το κανονικά. Αν το SmartScreen το σταματήσει, επιλέξτε τη δυνατότητα να το εκτελέσετε ούτως ή άλλως ("Run anyway" σε Windows στα αγγλικά). Το παράθυρο της προειδοποίησης ίσως χρειαστεί πρώτα να επεκταθεί: στο μηχάνημα με Windows 10 που δοκιμάστηκε, πρόσφερε μόνο ένα κουμπί για να μην εκτελεστεί το αρχείο, μέχρι να πατηθεί ο σύνδεσμος κάτω από το μήνυμά του. Το `.msi` για όλους τους χρήστες ζητά στη συνέχεια έγκριση διαχειριστή, όπως κάθε άλλο πρόγραμμα εγκατάστασης.
- **`.zip`** - εξαγάγετέ το και ξεκινήστε το `7zFM.exe` ή το `7z.exe` από τον φάκελο. Και τα προγράμματα μέσα σε αυτό είναι μη υπογεγραμμένα, οπότε τα Windows μπορεί να εμφανίσουν την ίδια προειδοποίηση την πρώτη φορά που θα ξεκινήσετε το καθένα.

Το SmartScreen προειδοποιεί με βάση το πόσο γνωστό είναι ένα αρχείο, όχι μόνο με βάση τις υπογραφές· ένα αρχείο που έχει κατέβει από λίγους ανθρώπους μπορεί να το προκαλέσει ακόμη και όταν είναι υπογεγραμμένο. Τίποτα εδώ δεν το αλλάζει αυτό, και τίποτα στα παραπάνω βήματα δεν απενεργοποιεί το SmartScreen.

### Smart App Control στα Windows 11

Ορισμένοι υπολογιστές με Windows 11 έχουν ενεργοποιημένη μια αυστηρότερη προστασία που ονομάζεται **Έξυπνος έλεγχος εφαρμογών**. Όταν είναι ενεργή, τα Windows μπλοκάρουν τα μη υπογεγραμμένα αρχεία, εκτός αν η υπηρεσία cloud της Microsoft μπορεί να τα εγγυηθεί, και μια νέα έκδοση συνήθως δεν έχει τέτοια καταγραφή ([Microsoft][sac-faq], [Microsoft][smartscreen-rep]). Σε αντίθεση με την προειδοποίηση του SmartScreen, το μπλοκάρισμα δεν έχει επιλογή για να εκτελεστεί το αρχείο ούτως ή άλλως, και οι συχνές ερωτήσεις της Microsoft λένε ότι δεν υπάρχει τρόπος να παρακαμφθεί το Smart App Control για μεμονωμένη εφαρμογή.

Τι συνέβη όταν το 7-ZSTar 26.05.1 δοκιμάστηκε σε Windows 11 Pro 25H2 (build 26200.8037) με ενεργοποιημένο το Smart App Control:

- **Τα προγράμματα εγκατάστασης `.msi` μπλοκαρίστηκαν**, τόσο εκείνο για όλους τους χρήστες όσο και εκείνο ανά χρήστη. Σε Windows με παραδοσιακά κινεζικά, το Windows Installer έδειξε το μήνυμα 「系統禁用此安裝。請連絡系統管理員。」, και μια ειδοποίηση της εφαρμογής Ασφάλεια των Windows έλεγε ότι το Smart App Control μπλόκαρε το αρχείο επειδή τα Windows δεν μπορούσαν να καταλάβουν ποιος το δημοσίευσε και δεν είναι εφαρμογή που τα Windows γνωρίζουν. Δεν υπήρχε επιλογή συνέχισης, και το `msiexec /i ... /qn` επέστρεψε το σφάλμα 1625. Αυτό το μήνυμα είναι η συμβολοσειρά 1625 του Windows Installer· σε Windows στα αγγλικά η ίδια συμβολοσειρά γράφει "The system administrator has set policies to prevent this installation." (διαβασμένη από τους αγγλικούς πόρους του Windows Installer, δεν εμφανίστηκε στην οθόνη).
- **Ένα πρόγραμμα από το `.zip` εκτελέστηκε.** Το `7zFM.exe`, εξαγμένο από το φορητό `.zip`, ξεκίνησε κανονικά στην ίδια δοκιμή. Το αν τα Windows επιτρέπουν σε ένα μη υπογεγραμμένο πρόγραμμα να εκτελεστεί είναι δική τους κρίση για εκείνο το αρχείο, επομένως στον δικό σας υπολογιστή μπορεί να είναι διαφορετικό.
- Αμέσως μετά την ενεργοποίηση του Smart App Control, το `.msi` εγκαταστάθηκε για λίγα λεπτά πριν αρχίσει να μπλοκάρεται. Η αιτία δεν βρέθηκε, οπότε μια επιτυχία αμέσως μετά την ενεργοποίησή του δεν σημαίνει ότι το πρόγραμμα εγκατάστασης επιτρέπεται.

Επομένως, σε έναν υπολογιστή όπου το Smart App Control είναι ενεργό, **τα προγράμματα εγκατάστασης δεν μπορούν να εγκατασταθούν**, και ο έλεγχος του `SHA256SUMS` δεν το αλλάζει. Αυτό που το αλλάζει είναι η απενεργοποίηση του Έξυπνου ελέγχου εφαρμογών στις Ρυθμίσεις του Έξυπνου ελέγχου εφαρμογών της εφαρμογής Ασφάλεια των Windows (στα Windows με παραδοσιακά κινεζικά που δοκιμάστηκαν: Windows 安全性, 應用程式與瀏覽器控制, 智慧型應用程式控制設定).
Στη δοκιμή, η επιλογή απενεργοποίησης τέθηκε σε ισχύ αμέσως χωρίς επανεκκίνηση, και στη συνέχεια τα προγράμματα εγκατάστασης εγκαταστάθηκαν. Πρόκειται για ρύθμιση ολόκληρου του υπολογιστή και τίποτα εδώ δεν σας ζητά να την αλλάξετε: η απόφαση είναι δική σας, ή του διαχειριστή σας σε έναν διαχειριζόμενο υπολογιστή.

Αξίζει επίσης να γνωρίζετε εκ των προτέρων αν μπορεί να ενεργοποιηθεί ξανά. Οι συχνές ερωτήσεις της Microsoft λένε ότι οι πρόσφατες ενημερώσεις των Windows επιτρέπουν την ξανά ενεργοποίηση του Smart App Control χωρίς καθαρή εγκατάσταση των Windows, οπότε σε μια έκδοση χωρίς αυτές, η απενεργοποίησή του μπορεί να είναι μόνιμη. Στο build που δοκιμάστηκε εδώ, η επιλογή ενεργοποίησης εξακολουθούσε να προσφέρεται μετά την απενεργοποίηση· αυτό είναι αποτέλεσμα δοκιμής, όχι υπόσχεση για την έκδοσή σας.

## Εγκατάσταση

Τρία πακέτα, όλα φτιαγμένα από το `installer\Build-Package.ps1` (εκείνο ανά χρήστη με `-PerUser`):

| | `.msi` | `-user.msi` | `.zip` |
|---|---|---|---|
| Εγκαθίσταται για | κάθε λογαριασμό | τον λογαριασμό που το εγκαθιστά | - |
| Μενού δεξιού κλικ στην Εξερεύνηση αρχείων | ναι | ναι, μόνο το κλασικό μενού ([παρακάτω](#το-πακέτο-ανά-χρήστη)) | όχι |
| Καταχώριση στο Μενού "Έναρξη" | ναι | ναι | όχι |
| Απαιτεί διαχειριστή | ναι | όχι | όχι |
| Αφαίρεση | *Εγκατεστημένες εφαρμογές* στις *Ρυθμίσεις* | *Εγκατεστημένες εφαρμογές* στις *Ρυθμίσεις* | διαγράψτε τον φάκελο |

Οι *Εγκατεστημένες εφαρμογές* είναι το όνομα στα Windows 11. Τα Windows 10 ονομάζουν την ίδια σελίδα *Εφαρμογές και δυνατότητες*, και στα Windows 7 είναι το *Programs and Features* στο *Control Panel* (Πίνακας Ελέγχου).

Χρησιμοποιήστε τα πακέτα που ταιριάζουν με τα ίδια τα Windows: x86 σε 32-bit Windows, x64 σε 64-bit Windows, arm64 σε Windows on Arm (τα πακέτα arm64 έχουν κατασκευαστεί αλλά δεν έχουν εκτελεστεί ποτέ). Η επέκταση κελύφους x86 είναι 32-bit και η 64-bit Εξερεύνηση αρχείων δεν μπορεί να τη φορτώσει, οπότε σε 64-bit Windows το x86 `-user.msi` δεν έχει καθόλου μενού δεξιού κλικ, και το x86 `.msi` έχει μόνο στα Windows 11 και μόνο για λογαριασμούς που κατέγραψαν το πακέτο του για τα Windows 11 (εκείνον που το εγκατέστησε, ή έναν που εκτέλεσε το `-Register`, παρακάτω).

Το MSI εγκαθίσταται στο `Program Files\7-ZSTar` - πάντα: σε αντίθεση με το πακέτο ανά χρήστη, δεν προσφέρει επιλογή φακέλου και αγνοεί το `INSTALLFOLDER` στη γραμμή εντολών, επειδή ο φάκελος αυτός περιέχει ένα σενάριο που το πρόγραμμα εγκατάστασης εκτελεί ως SYSTEM και ένα DLL που φορτώνει η Εξερεύνηση αρχείων κάθε χρήστη, και ένας φάκελος που δημιουργείται αλλού (π.χ. κάτω από το `C:\`) είναι εγγράψιμος από κάθε χρήστη. Καταχωρίζει το δικό του CLSID επέκτασης κελύφους και το δικό του κλαδί μητρώου `Software\7-ZSTar`, και ονομάζει κάθε κλειδί μενού περιβάλλοντος `7-ZSTar` - οπότε ούτε συγκρούεται με το επίσημο 7-Zip ούτε το αφαιρεί. Δείτε το [installer/GUIDS.md](../../installer/GUIDS.md).

Εκτελεί έναν κανονικό οδηγό εγκατάστασης - welcome, licence, setup type, optional feature tree, finish (καλωσόρισμα, άδεια χρήσης, τύπος εγκατάστασης, δέντρο προαιρετικών λειτουργιών, ολοκλήρωση) - και η αθόρυβη εγκατάσταση λειτουργεί αμετάβλητη (`msiexec /i 7-ZSTar-<version>-<arch>.msi /qn`), επειδή το msiexec παραλείπει ολόκληρη την ακολουθία διεπαφής στην αθόρυβη λειτουργία. Ο οδηγός είναι μόνο στα αγγλικά, ακόμη και σε Windows ρυθμισμένα σε άλλη γλώσσα (παρατηρήθηκε σε Windows 10 με παραδοσιακά κινεζικά· το `.msi` κατασκευάζεται χωρίς άλλη γλώσσα), και η τελευταία του σελίδα έχει το *Launch 7-ZSTar File Manager* (εκκίνηση του διαχειριστή αρχείων 7-ZSTar) επιλεγμένο από προεπιλογή.

### Μενού δεξιού κλικ των Windows 11

Στα Windows 11 η καταχώριση βρίσκεται στο μενού πρώτου επιπέδου, όχι θαμμένη κάτω από το *Εμφάνιση περισσότερων επιλογών* όπου εξακολουθούν να βρίσκονται το επίσημο 7-Zip και το WinRAR. Τα Windows 11 εμφανίζουν εκεί μια επέκταση κελύφους μόνο όταν αυτή συνοδεύεται από ταυτότητα πακέτου, οπότε το MSI περιλαμβάνει ένα μικρό πακέτο MSIX μόνο με ταυτότητα δίπλα στο πρόγραμμα και το καταχωρίζει κατά την εγκατάσταση. Διατηρείται επίσης η κλασική καταχώριση. Αυτή είναι που βάζει την καταχώριση στο μενού δεξιού κλικ στα Windows 10 και στα Windows 7, των οποίων το μενού έχει ένα μόνο επίπεδο χωρίς *Εμφάνιση περισσότερων επιλογών*, και που τη διατηρεί σε λειτουργία για όσους έχουν επαναφέρει το παλιό μενού περιβάλλοντος.

Αυτό το πακέτο είναι υπογεγραμμένο με **αυτο-υπογεγραμμένο πιστοποιητικό**, και το πρόγραμμα εγκατάστασης το τοποθετεί στο `LocalMachine\TrustedPeople` - τα Windows δεν θα αναπτύξουν ένα πακέτο του οποίου την υπογραφή δεν μπορούν να συνδέσουν με κάτι αξιόπιστο. Η απεγκατάσταση αφαιρεί το πιστοποιητικό μαζί με το πακέτο. Στα Windows 10 και στα Windows 7 το πρόγραμμα εγκατάστασης δεν κάνει κανένα από τα δύο: δεν προσθέτει πιστοποιητικό και δεν καταχωρίζει πακέτο, και η κλασική καταχώριση από μόνη της παρέχει το μενού.

Αν προτιμάτε να μην εμπιστευτείτε ένα αυτο-υπογεγραμμένο πιστοποιητικό, αρνηθείτε μόνο αυτό το τμήμα και κρατήστε όλα τα υπόλοιπα:

```
msiexec /i 7-ZSTar-<version>-<arch>.msi SPARSE=0
```

Τότε παίρνετε μόνο το κλασικό μενού, οπότε στα Windows 11 η καταχώριση του 7-ZSTar βρίσκεται στο μενού δεξιού κλικ κάτω από το *Εμφάνιση περισσότερων επιλογών*. Για να ενεργοποιήσετε αργότερα την καταχώριση του πρώτου επιπέδου, ή για να την αναιρέσετε μετά από μια κανονική εγκατάσταση:

```
powershell -ExecutionPolicy Bypass -File "C:\Program Files\7-ZSTar\Setup-ShellIntegration.ps1" -TrustCert -Register
powershell -ExecutionPolicy Bypass -File "C:\Program Files\7-ZSTar\Setup-ShellIntegration.ps1" -Unregister -UntrustCert
```

Η εμπιστοσύνη σε αυτό το πιστοποιητικό σημαίνει ότι τα Windows θα δεχτούν χωρίς προειδοποίηση και **οποιοδήποτε άλλο** πακέτο υπογεγραμμένο με το ίδιο κλειδί. Χρησιμοποιείται μόνο για αυτό το ένα πακέτο, και η απεγκατάσταση το αφαιρεί ξανά, αλλά αυτό είναι που αποδέχεστε - το `SPARSE=0` παραπάνω είναι ο τρόπος να το αρνηθείτε.

Η καταχώριση πακέτου γίνεται ανά χρήστη, και το πρόγραμμα εγκατάστασης την εκτελεί μόνο για όποιον έκανε την εγκατάσταση. Δύο συνέπειες:

- Ένας δεύτερος λογαριασμός στο ίδιο μηχάνημα παίρνει μόνο το κλασικό μενού, μέχρι να εκτελέσει το ίδιο σενάριο με `-Register`.
- Η απεγκατάσταση αναιρεί την καταχώριση μόνο για όποιον κάνει την απεγκατάσταση. Αν την έχει καταχωρίσει κάποιος άλλος, η καταχώρισή του επιβιώνει της απεγκατάστασης και δείχνει σε φάκελο που δεν υπάρχει πια· ο λογαριασμός αυτός την καθαρίζει με
  `Get-AppxPackage 7-ZSTar | Remove-AppxPackage`.

**Γνωστός περιορισμός: το μενού πρώτου επιπέδου καταχωρίζεται μόνο όταν η εγκατάσταση εκτελείται σε διαδραστική συνεδρία με συνδεδεμένο χρήστη.** Αν εγκαταστήσετε το `.msi` για όλους τους χρήστες από απομακρυσμένη ή μη διαδραστική συνεδρία - μέσω SSH, ή σε αθόρυβη ανάπτυξη από εργαλείο διαχείρισης - αναφέρεται και πάλι επιτυχία, αλλά το πακέτο των Windows 11 δεν καταχωρίζεται, οπότε εμφανίζεται μόνο το κλασικό μενού κάτω από το *Εμφάνιση περισσότερων επιλογών*. Στη δοκιμή, το `msiexec /i ... /qn` από συνεδρία SSH (συνεδρία 0) τερμάτισε με 0, ενώ το `Setup-ShellIntegration.ps1` ανέφερε `registration failed: 0x80070005` (άρνηση πρόσβασης)· το ίδιο `.msi` που εγκαταστάθηκε από τη συνεδρία κονσόλας ενός διαχειριστή καταχωρίστηκε κανονικά.

Το `-Status` εκτυπώνει τι υπάρχει και τι δεν υπάρχει στη θέση του.

### Το πακέτο ανά χρήστη

Το `7-ZSTar-<version>-<arch>-user.msi` εγκαθίσταται μόνο για τον τρέχοντα λογαριασμό, στο `%LOCALAPPDATA%\Programs\7-ZSTar`, χωρίς προτροπή του Ελέγχου λογαριασμού χρήστη (UAC). Ό,τι καταχωρίζει πηγαίνει κάτω από το `HKCU`· το πακέτο δεν γράφει τίποτα στο `HKLM` (εκτός από τη δική του λογιστική του Windows Installer). Τι δεν κάνει με τον τρόπο που το κάνει το πακέτο ανά υπολογιστή:

- **Μενού πρώτου επιπέδου στα Windows 11: καθόλου.** Στα Windows 11, το 7-ZSTar βρίσκεται στο μενού δεξιού κλικ κάτω από το *Εμφάνιση περισσότερων επιλογών*. Η καταχώριση πρώτου επιπέδου απαιτεί το αυτο-υπογεγραμμένο πιστοποιητικό να είναι αξιόπιστο σε όλο το μηχάνημα, κάτι που απαιτεί διαχειριστή: μετρήθηκε στα Windows 11 ότι ένα πιστοποιητικό στο `CurrentUser\TrustedPeople` δεν αρκεί για να αναπτύξουν τα Windows το πακέτο. Έτσι το πακέτο ανά χρήστη το παραλείπει.
- **Ένα από τα δύο ανά μηχάνημα.** Κάθε πακέτο αρνείται να εγκατασταθεί όσο είναι εγκατεστημένο το άλλο· απεγκαταστήστε το ένα πριν εγκαταστήσετε το άλλο. Το πακέτο ανά υπολογιστή βλέπει μόνο το αντίγραφο ανά χρήστη του λογαριασμού που το εκτελεί, οπότε η εγκατάσταση ανά χρήστη ενός άλλου λογαριασμού δεν ανιχνεύεται.
- **Η Πολιτική ομάδας μπορεί να κρύψει το μενού του.** Όπου έχει οριστεί το `EnforceShellExtensionSecurity`, η Εξερεύνηση αρχείων φορτώνει μόνο επεκτάσεις κελύφους που αναφέρονται κάτω από το κλειδί *Approved* ολόκληρου του μηχανήματος, στο οποίο μια εγκατάσταση ανά χρήστη δεν μπορεί να γράψει, οπότε το μενού δεξιού κλικ δεν εμφανίζεται. Χρησιμοποιήστε εκεί το πακέτο ανά υπολογιστή.
- **Ο καθαρισμός μιας μορφής στο Εργαλεία > Ρυθμίσεις > Σύστημα αφαιρεί και την προσφορά του 7-ZSTar για αυτήν.** Όταν καθαρίζετε εκεί μια μορφή (πατήστε στο κελί της μέχρι να αδειάσει, μετά OK), ο διαχειριστής αρχείων διαγράφει ολόκληρα τα κλειδιά `HKCU\Software\Classes\.<ext>` και `7-ZSTar.<ext>` - και σε μια εγκατάσταση ανά χρήστη αυτά τα κλειδιά περιέχουν επίσης ό,τι καταχώρισε το πακέτο για τις Ρυθμίσεις > Εφαρμογές > Προεπιλεγμένες εφαρμογές και τη λίστα *Άνοιγμα με*. Το 7-ZSTar τότε εξαφανίζεται από το *Άνοιγμα με* για αυτή τη μορφή, και οι Προεπιλεγμένες εφαρμογές δείχνουν μια κενή καταχώριση για αυτήν. Η επιδιόρθωση της εγκατάστασης την επαναφέρει (εκτελέστε ξανά το `.msi` και επιλέξτε *Repair*). Καλύτερα, αναθέτετε τους τύπους αρχείων στις Προεπιλεγμένες εφαρμογές αντί για τον διαχειριστή αρχείων. Το πακέτο ανά υπολογιστή έχει το ίδιο αδύναμο σημείο σε ένα σημείο, που περιγράφεται παρακάτω στις συσχετίσεις αρχείων.

### Συσχετίσεις αρχείων και τι κάνει σε αυτές η απεγκατάσταση

**Ορίστε τις στις Ρυθμίσεις > Εφαρμογές > Προεπιλεγμένες εφαρμογές.** Στα Windows 11, πληκτρολογήστε εκεί 7-ZSTar και κάθε μορφή που μπορεί να ανοίξει εμφανίζεται για ανάθεση. Στα Windows 10, το 7-ZSTar εμφανίζεται κάτω από το *Set defaults by app* σε εκείνη τη σελίδα, όπου το *Manage* δείχνει τις μορφές του. Τα Windows 7 δεν έχουν την εφαρμογή *Settings* (Ρυθμίσεις): το 7-ZSTar εμφανίζεται στο Control Panel (Πίνακας Ελέγχου) > Προεπιλεγμένα προγράμματα > *Ορίστε τα προεπιλεγμένα σας προγράμματα*, και αυτό εννοεί το *Προεπιλεγμένες εφαρμογές* σε αυτόν τον οδηγό εκεί. Η ανάθεση μορφών από αυτές τις δύο σελίδες δεν έχει δοκιμαστεί. Το πρόγραμμα εγκατάστασης καταχωρίζει το 7-ZSTar ως εφαρμογή των Προεπιλεγμένων προγραμμάτων - ένα ProgID ανά μορφή με το εικονίδιο και την εντολή ανοίγματός του, μια καταχώριση στη λίστα *Άνοιγμα με* κάθε επέκτασης, και το μπλοκ Capabilities που διαβάζουν τα Windows - αλλά σκόπιμα δεν διεκδικεί κανέναν τύπο αρχείου: το ποιο πρόγραμμα ανοίγει τα αρχεία σας είναι δική σας απόφαση, και αυτό είναι που κρατά το 7-ZSTar και το επίσημο 7-Zip να μην εμποδίζει το ένα το άλλο. Τα Windows μπορούν ακόμη να στείλουν μια μορφή στο 7-ZSTar από μόνα τους όταν κανένα άλλο πρόγραμμα δεν προσφέρεται να την ανοίξει: στα μηχανήματα με Windows 10 και Windows 7 που δοκιμάστηκαν, όπου τίποτε άλλο δεν είχε καταχωρίσει το `.7z`, ένα αρχείο `.7z` έδειχνε το εικονίδιο του 7-ZSTar και ανοιγόταν σε αυτό με διπλό κλικ, χωρίς να ρωτήσουν τα Windows ποιο πρόγραμμα να χρησιμοποιηθεί.

**Το Εργαλεία > Ρυθμίσεις > Σύστημα στον διαχειριστή αρχείων ως επί το πλείστον δεν λειτουργεί στα Windows 11**, και αυτό είναι κανόνας των Windows και όχι σφάλμα εδώ. Γράφει ένα ProgID `7-ZSTar.<ext>` στο `HKCU\Software\Classes`, και για κάθε επέκταση που το μηχάνημα ήδη γνωρίζει - κάθε μορφή αρχείου συμπίεσης - τα Windows 11 το αγνοούν: το `AssocQueryString` απαντά `Unknown` και η Εξερεύνηση αρχείων σχεδιάζει το κενό γενικό εικονίδιο. Αυτό που σέβονται αντί γι' αυτό είναι ένα κλειδί `UserChoice` σφραγισμένο με ένα hash που μόνο τα Windows μπορούν να υπολογίσουν, γι' αυτό η διεπαφή των Ρυθμίσεων είναι εκεί η μόνη διαδρομή. Καμία εφαρμογή δεν μπορεί να γράψει ένα: ούτε το 7-ZSTar, ούτε το 7-Zip, ούτε κανένα πρόγραμμα εγκατάστασης. Τα Windows 10 και Windows 7 συμπεριφέρθηκαν διαφορετικά στις δοκιμές: μόλις τα `.7z` και `.zst` ορίστηκαν στον διαχειριστή αρχείων, χωρίς να έχει επιλεγεί άλλο πρόγραμμα για αυτά, το `AssocQueryString` επέστρεψε `7zFM.exe` και για τα δύο.

**Ο καθαρισμός μιας μορφής στη στήλη της *Ολοι οι χρήστες* αφαιρεί τη δική του καταχώριση του πακέτου ανά υπολογιστή για αυτήν.** Αυτή η στήλη γράφει στο `HKLM\Software\Classes`, όπου το πακέτο ανά υπολογιστή κρατά τα ProgID και τις καταχωρίσεις *Άνοιγμα με* που διαφημίζει, και ο καθαρισμός μιας μορφής εκεί (που απαιτεί τον διαχειριστή αρχείων να εκτελείται ως διαχειριστής) διαγράφει ολόκληρα αυτά τα κλειδιά - για κάθε λογαριασμό. Η επιδιόρθωση επανέφερε τα ίδια κλειδιά για το πακέτο ανά χρήστη· για αυτό εδώ δεν μετρήθηκε.

**Ένα εικονίδιο που μένει κενό μετά από οποιαδήποτε αλλαγή** μπορεί επίσης να οφείλεται στην προσωρινή μνήμη εικονιδίων της Εξερεύνησης αρχείων, η οποία δεν αντιλαμβάνεται ότι ένα DLL που έχει ήδη αποθηκεύσει έχει αντικατασταθεί· το `ie4uinit.exe -show` δεν την καθαρίζει αξιόπιστα. Κλείστε την Εξερεύνηση αρχείων, διαγράψτε το `%LOCALAPPDATA%\Microsoft\Windows\Explorer\iconcache_*.db`, ξεκινήστε την ξανά.

**Η απεγκατάσταση αφαιρεί τις συσχετίσεις στις οποίες φτάνει** - τα ProgID `7-ZSTar.*` που ανήκουν σε όποιον κάνει την απεγκατάσταση, και μόνο τους τύπους αρχείων που εξακολουθούν να δείχνουν σε αυτά, οπότε μια μορφή που στο μεταξύ δόθηκε σε άλλο πρόγραμμα μένει ανέγγιχτη. Η απεγκατάσταση του πακέτου ανά υπολογιστή αφήνει επίσης ανέγγιχτο ένα ProgID που ανοίγει ένα αντίγραφο του 7-ZSTar κάπου αλλού που εξακολουθεί να υπάρχει - ένα φορητό από το `.zip`, ρυθμισμένο με το δικό του αντίγραφο του **Εργαλεία > Ρυθμίσεις > Σύστημα**. Το πακέτο ανά χρήστη δεν μπορεί: τα ProgID του είναι αυτά ακριβώς τα κλειδιά `HKCU` (δείτε το *Το πακέτο ανά χρήστη* παραπάνω), και η απεγκατάστασή του τα αφαιρεί όποιος κι αν τα έγραψε τελευταίος. Αν τα άφηνε πίσω, αυτοί οι τύποι θα έδειχναν σε ένα ProgID του οποίου το εικονίδιο και η εντολή είναι ένα διαγραμμένο εκτελέσιμο, δηλαδή κενό εικονίδιο και σφάλμα στο διπλό κλικ. Οι συσχετίσεις των άλλων λογαριασμών είναι εκτός εμβέλειας· μπορούν να καθαρίσουν τις δικές τους με `Setup-ShellIntegration.ps1 -RemoveAssociations` πριν φύγει το πρόγραμμα. Το `msiexec /x ... KEEPASSOC=1` το παραλείπει, και μια αναβάθμιση δεν το κάνει ποτέ.

**Γνωστός περιορισμός: οι άλλοι λογαριασμοί κρατούν τις συσχετίσεις που όρισαν οι ίδιοι.** Η απεγκατάσταση του πακέτου ανά υπολογιστή καθαρίζει μόνο ό,τι όρισε ο λογαριασμός που εκτελεί την απεγκατάσταση στη δική του στήλη (με επικεφαλίδα το όνομα του λογαριασμού) κάτω από το **Εργαλεία > Ρυθμίσεις > Σύστημα** στον διαχειριστή αρχείων. Κάθε άλλος λογαριασμός που όρισε συσχετίσεις εκεί τις κρατά, δείχνοντας στο αφαιρεμένο πρόγραμμα, οπότε το διπλό κλικ σε ένα αρχείο `.7z` ρωτά τα Windows ποιο πρόγραμμα να χρησιμοποιηθεί. Κάθε λογαριασμός πρέπει να καθαρίσει τις δικές του **πριν** από την απεγκατάσταση, με

```
powershell -ExecutionPolicy Bypass -File "C:\Program Files\7-ZSTar\Setup-ShellIntegration.ps1" -RemoveAssociations
```

το οποίο αφαιρεί μόνο τις καταχωρίσεις του 7-ZSTar, ή μετά να αναθέσει ξανά τους τύπους στις Ρυθμίσεις > Εφαρμογές > Προεπιλεγμένες εφαρμογές. Για να το κάνετε αντί γι' αυτό στον διαχειριστή αρχείων, πατήστε κάθε κελί στη δική του στήλη που δείχνει 7-ZSTar μέχρι να αδειάσει, μετά OK· μην επιλέξετε όλες τις γραμμές και πατήσετε "+", που εφαρμόζει μία κατάσταση σε όλες τις επιλεγμένες γραμμές και επομένως καθαρίζει και μορφές που ανήκουν σε άλλο πρόγραμμα, όπως το επίσημο 7-Zip.

Οι συσχετίσεις που ορίστηκαν στη στήλη **Ολοι οι χρήστες** δεν τις αγγίζει καθόλου ο καθαρισμός της απεγκατάστασης, και μένουν να δείχνουν κάθε λογαριασμό στο αφαιρεμένο πρόγραμμα. Διαχειριστής που όρισε κάποιες πρέπει να καθαρίσει αυτά τα κελιά, από διαχειριστή αρχείων που εκτελείται ως διαχειριστής (Εκτέλεση ως διαχειριστής), μετά OK, πριν από την απεγκατάσταση· το `-RemoveAssociations` δεν φτάνει σε αυτή τη στήλη. Ο καθαρισμός της ακριβώς πριν από μια απεγκατάσταση είναι ακίνδυνος, παρότι διαγράφει τη δική του καταχώριση του πακέτου εκεί (παραπάνω), αφού η απεγκατάσταση την αφαιρεί ούτως ή άλλως. Το πακέτο ανά χρήστη δεν έχει το πρόβλημα των άλλων λογαριασμών, και το επίσημο 7-Zip συμπεριφέρεται με τον ίδιο τρόπο.

## Γλώσσες

Κάθε πακέτο περιλαμβάνει τις μεταφράσεις του upstream, πάνω από 90 γλώσσες. Διαλέξτε μία από το **Εργαλεία > Ρυθμίσεις > Γλώσσα**· το MSI σας επιτρέπει επίσης να τις παραλείψετε κάτω από την *Custom* εγκατάσταση (προσαρμοσμένη). Το 7-ZSTar προσπαθεί να ακολουθήσει τη γλώσσα του συστήματος στην πρώτη εκτέλεση, αλλά αυτή η ανίχνευση τα παρατά και μένει στα αγγλικά όταν η "language for non-Unicode programs" (γλώσσα για προγράμματα που δεν υποστηρίζουν Unicode) και η ρύθμιση «Τοπική μορφή» των Windows διαφωνούν - η επιλογή γλώσσας με το χέρι λειτουργεί πάντα.

Τα κείμενα που πρόσθεσε το ίδιο το 7-ZSTar - τα πεδία επιπέδου και λεξικού του zstd, τα ονόματα των νέων μορφών αρχείων - δεν έχουν μετάφραση του upstream και μένουν στα αγγλικά. Εξαίρεση αποτελούν τα κουμπιά **Δωρεά** και **Ιστότοπος** του παραθύρου «Περί του 7-ZSTar»: 67 από τις 92 γλώσσες έχουν δική τους λέξη για καθένα από τα δύο κουμπιά, ενώ οι άλλες 25 εμφανίζουν τα αγγλικά (το `Lang/UPSTREAM.md` τις απαριθμεί).
Οι μεταφράσεις είναι ενσωματωμένες από το upstream, δεν γράφονται εδώ: δείτε το [Lang/UPSTREAM.md](../../Lang/UPSTREAM.md).
